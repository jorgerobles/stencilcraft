## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] roxmltree added as a direct dependency of stencilcraft-svg**
- The shared `craft_svg::paths::import` flattens `<g>` and exposes no group chain, so `crates/svg` re-walks the XML with roxmltree (already in the build via craft-svg) to rebuild the group tree. Touches `Cargo.toml`, `crates/svg/Cargo.toml`, `Cargo.lock` beyond the plan's file list. Alignment with emitted shapes is by document order; if CSS-driven hiding desynchronizes the counts, grouping is skipped (hints still returned), so `validate()` always passes.
- Committed in: `1f82230`

**2. [Rule 1 - Bug] Pre-existing stale goldens/tests on this branch**
- The v2 model made the default base layer operation-less (`data-kind="none"`), but `export_includes_board_size_in_viewbox` and the export goldens still expected `"cut"` — they failed before this plan ran. Updated the assertion and regenerated `crates/svg/tests/golden/*.svg` via `UPDATE_GOLDEN=1` (diff reviewed: only `data-kind`/class drift from the base-layer change).
- Committed in: `1f82230`

**3. [Rule 1 - Semantic ripple] Existing layer-based import tests moved to legacy mode**
- Tests asserting layer structure (colours, CSS cascade, use-inherited style) now run through `ImportPolicy { legacy_style_operations: true }` to keep covering the legacy path; geometry tests assert unassigned shapes in the new mode.
- Committed in: `1f82230`

### App-level note

**4. [Deviation - documented] App SVG import no longer applies ImportOptions join/fit**
- `import_svg` now calls `stencilcraft_svg::import_bytes_with_warnings_policy` directly (needed so hints + the legacy flag reach the app); the `join` post-processing from `stencilcraft_import::import_file` defaults is not applied to app-side SVG imports. CLI/other formats unchanged. If join parity is required in the app, thread the policy through `crates/import` in a follow-up.

**Total deviations:** 4 (1 blocking dep, 3 documented fixes/notes). No scope creep beyond making the plan's semantics testable.
