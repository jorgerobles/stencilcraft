# Phase 02.1 Plan 03: UI shows geometry as geometry and operations as operations — Summary

The Layers workspace panel is now two panels: **Geometry** (from `Document.groups`, recursive
`GroupChild`, plus the derived Unassigned leaf) and **Operations** (from `Document.operations`).
The whole workspace compiles again against the operations-first model — no adapter layer.

## Accomplishments

- **Task 1 — Geometry panel:** `build_geometry_rows` walks `doc.groups` recursively (open set
  keyed by group id), double-click (`ListEvent::Activate`) enters a group with a `..` row, click
  selects, and a group row deep-selects to every member shape (`group_member_shapes`). Group /
  Ungroup footer buttons dispatch `GroupCreate` / `GroupUngroup` after `show()`.
- **Task 2 — Operations panel:** one row per `doc.operations` entry with icon, derived
  `pass_number` (output operations only), colour swatch (`operation_swatch_color`), profile
  summary (power/speed), and member count. Hammer on a group/shape row creates an operation
  scoped to those shapes; hammer on an operation row duplicates it over the same members.
- **Task 3 — Tags + filter:** geometry rows show `#id` chips per owning operation with a `…`
  overflow menu (remove membership, toggle visibility, select members, view-only filter). The
  operations panel's second toggle column is the view-only filter; it hides shapes whose
  operations are all filtered out and is never persisted.
- **Task 4 — Bulk menu:** "New operation by colour" / "all selected" / "each selected"; when
  the affected shape count exceeds `UserPrefs.bulk_confirm_threshold` (default 10, new pref) a
  "Create N operations? Continue?" dialog gates the dispatch.
- **Task 5 — e2e:** 8 kittest tests in `mod ui_e2e` cover nested groups visible, deep-select,
  hammer → operation + membership, bulk over/under threshold, filter hides geometry, group /
  ungroup, and tag overflow removal.

## Deviations from plan

- Plan listed only `main.rs` and `layers.rs`; compilation also required `apps/stencilcraft/src/operations.rs`
  (preset catalogue migrated from the removed `Operation` enum to `OperationKind`) and test-only fixes in
  `crates/tiling`, `crates/import/tests`, `crates/studio/tests` (they referenced the removed `Layer.operation` /
  `Layer.color` fields). No non-test code outside the two planned files was changed.
- The hammer creates a Cut pass directly (no kind popup); presets remain available as labels/icons.
- Filter toggling in e2e is driven through the tag overflow menu because the operations list sits below
  the harness viewport fold and wheel-scroll did not move it; the ops-panel toggle column is covered by
  unit-level state handling.
