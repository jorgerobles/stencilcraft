# Phase 2.1: Geometry/Operations Separation - Context

**Gathered:** 2026-11-25
**Status:** Ready for planning
**Inserted between:** Phase 2 and Phase 3 (urgent insertion; Phase 3 output depends on this model)

<domain>
## Phase Boundary

Correct the conflation found during Phase 2 verification: imported geometry must stay
untouched (source `<g>` nesting is preserved as document groups), and operations become
distinct production entities created by the user from a layer, group, or selection.

Phase 2.1 fixes the importer and promotes operations to first-class document entities
(`Document.operations`). It does not change G-code emission (Phase 3), job planning
(Phase 4), or add streaming.

</domain>

<decisions>
## Implementation Decisions

- **D-01 (single model change):** No published v2 exists, so the model is revised in
  place: `Document.operations` becomes the production entity and `Layer` becomes
  geometry-only. No A-adapter, no version bump, no v2→v3 migration. — *Reversibility:
  costly, but there is no published format to protect.*
- **D-02 (import):** SVG/DXF `<g>` nesting imports into `Document.groups`, not into
  operation layers. No operations are synthesized from source styling by default.
  — *Reversibility: costly; documented by ADR, old behaviour kept behind a pref.*
- **D-03 (import hints):** `data-kind`/class/style become non-binding hints returned by
  the importer and surfaced in the UI ("found N engrave groups — apply?"), never applied
  silently. — *Reversibility: reversible.*
- **D-04 (legacy mode):** `UserPrefs.import_legacy_style_operations` (default `false`)
  reproduces the Phase-2 semantics (groups→layers, style→operation) for one release.
  — *Reversibility: reversible.*
- **D-05 (hammer):** The hammer on a layer/group/selection creates an operation scoped to
  it; membership uses `OperationAddMembers`. Selecting a layer scopes the operation to
  that layer's members. — *Reversibility: reversible.*
- **D-06 (identity):** An operation has a stable id, icon, number (derived pass order),
  colour, and baked profile (`OperationSettings`). Colour is display/filter only, never
  identity. — *Reversibility: reversible.*
- **D-07 (bulk):** "New by colour", "New all selected", "New each selected". When the
  affected shape count exceeds `UserPrefs.bulk_confirm_threshold` (default 10), show a
  simple confirm ("Create N operations? Continue?"). Preference-driven. — *Reversibility: reversible.*
- **D-08 (geometry tree):** The geometry panel renders `Group`/`GroupChild` with
  enter-group/deep-select and group/ungroup using the existing `GroupCreate`/`GroupUngroup`
  engine commands. — *Reversibility: reversible (UI) / costly (interaction model).*
- **D-09 (tags/filter):** Geometry rows show operation tags (id + colour) with a `…`
  overflow menu; a view-only filter hides/shows geometry assigned to chosen operations.
  — *Reversibility: reversible.*
- **D-10 (gates):** Light GSD. No per-plan RESEARCH/PATTERNS/VALIDATION/UI-SPEC gates;
  reuse `01-PATTERNS.md`, `02-PATTERNS.md`, and CodeGraph. Per plan: fmt, clippy
  `-D warnings`, targeted tests. One `xtask ci` at phase end only.
- **D-11 (v1):** v1 documents still migrate — directly to the revised model in one hop;
  geometry and production data must survive. — *Reversibility: costly.*
