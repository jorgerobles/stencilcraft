# Phase 02.1 Plan 02: Operations as first-class document entities — Summary

`Document.operations` is now the production entity; `Layer` is geometry-only. The v2 envelope was revised in place (no version bump, no v2→v3 migration — v2 was never published), and v1 migrates in one hop with geometry, colour, settings, visibility, lock and order preserved.

## Accomplishments

- **craft-libs model** (commit `24f2a74` on `phase-1-v2-model`): `Operation { id, name, kind, settings, color, visible, locked, members, icon }` and `Document.operations`; `OperationKind` unit enum replaces the settings-carrying `Operation` enum; `Layer` reduced to `{ name, visible, locked, members }`; new `operations` wire field in `craft-stencilcraft-format::DocumentFields`; `production_sequence`/`unassigned_shapes`/`operation_of_shape`/`next_operation_id` over operations; validation covers duplicate operation ids and dangling members.
- **v1 migration in one hop**: each v1 layer becomes one geometry layer holding all its shapes plus one `Operation` per distinct effective pass (first-appearance order), carrying the v1 colour/visibility/lock; template layers become a single `Guide` operation.
- **StencilCraft rev pins** bumped to `24f2a743d977183688905c86df2177357ed4769b` in all four `file://` entries + `cargo update` (commit `625012d`).
- **Engine** (commit `6a141e1`): `operation.create/add-members/remove-members/set-kind/set-settings/set-color/set-visible/set-locked/move/delete`, all undoable through the existing history snapshots; deprecated `Layer*` aliases re-pointed at operations; shape placement (trace, text, pathfinder, duplicate, set-style, replicas) joins the matching operation.
- **CLI + MCP** (commit `a465fd6`): `layer_paths` iterates output operations (pass order = operations order); MCP `doc.open`/`doc.summary` report `operations`; `trace` builds a Cut operation over traced shapes.
- **Tests**: v1 fixture migration (geometry + production lossless, incl. tool-passes fixture), N:M membership, multi-pass order round-trip, geometry-unchanged, hostile input, engine operation lifecycle + undo. 57 craft-stencilcraft-document tests, 116 engine tests, 57 CLI tests pass.

- StencilCraft: `cargo fmt --check` OK; `cargo clippy -p stencilcraft-engine -p stencilcraft-cli --all-targets -- -D warnings` clean; engine 116 + CLI 57 tests pass; doc/svg/kerf/layout/import/gcode/tiling/dxf/pdf/studio/testkit/mcp suites pass.

## Deviations from Plan

- None blocking. UI (`crates/ui-egui`, `apps/stencilcraft`) intentionally not updated this wave per plan; they do not compile against the new model and are wave 3's scope (gates cover engine + CLI only).
- `LayerSetOperation`/`LayerAdd` command params changed from a full operation object to a plain `OperationKind` string (deprecated aliases; command JSON is not a published format).
- SVG golden files regenerated: export now emits one group per operation with `data-kind` from the operation (`cut` instead of `none` on the base pass).

## Known Stubs

- `apps/stencilcraft` and `crates/ui-egui` still reference the removed `Layer.operation`/`Layer.color` fields — wave 3 replaces them with operation-panel code.
