<objective>
**User story (derived from the ROADMAP Phase 2 goal):** **As a** StencilCraft user, **I want to** build an ordered operation stack and assign any selection of objects to it, **so that** each shape is cut, scored, or engraved in the right passes without moving its geometry.

This plan is the Wave 2 expansion on the 02-01 tracer: migrate the engine, ui-egui, MCP, apps, and CLI/tests from v1 call sites to the pinned v2 model behind a full workspace compile gate, then add the engine commands and preset catalogue the UI waves will call. It deliberately contains no Layers-panel UI.

Purpose: 02-01 proved the pin and migrated the library crates; the engine/apps/UI still reference `Layer.kind`, `Layer.shapes`, and `Shape.style`, so nothing can compile until they are migrated. The new additive membership and operation commands are the only mutation surface the UI may use (D-16), so they must exist and be tested before any panel work.

Output: a compiling workspace on the v2 model, additive membership/operation/reorder commands with geometry-invariance tests, and the built-in operation-preset catalogue. No UI wiring.
</objective>
