<objective>
**User story (derived from the ROADMAP Phase 2 goal):** **As a** StencilCraft user, **I want to** build an ordered operation stack and assign any selection of objects to it, **so that** each shape is cut, scored, or engraved in the right passes without moving its geometry.

This plan is the Wave 1 tracer for that goal: publish the uncommitted Phase 1 v2 model on a local branch, re-point the worktree's four storytold dependencies to that captured rev, and migrate the library crates behind a compile gate. It delivers the derived `production_sequence()` / `unassigned_shapes()` primitives that UI-04 and UI-06 depend on, and leaves the workspace in a state where 02-02 can migrate the engine/apps/UI against a stable pin. It deliberately contains no engine command work and no UI.

Purpose: the worktree currently pins the v1 model (`Layer.kind`, `Layer.shapes`, `Shape.style`) while Phase 1's v2 model exists only as uncommitted changes in `refs/craft-libs`; nothing downstream can call `Layer.members` or `Document::unassigned_shapes()` until the pin moves and the library call sites are migrated. This tracer proves that pin-and-migrate path end-to-end on the library crate group before the much larger engine/app migration in 02-02 spends context against it.

Output: a committed `phase-1-v2-model` branch, a worktree pinned to it with a regenerated `Cargo.lock`, and a green `cargo check` over the twelve library crates. No engine commands, no preset catalogue, no UI.
</objective>
